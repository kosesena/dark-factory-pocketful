## Suggested test (non-blocking)
- F15: `Authorization: Basic <valid token>` must be 401 ("Missing, malformed or unknown bearer
  token"). The code is correct, but only the auditor probe would catch a regression. Add it to `stage-1/tests`.

## Behaviour the spec does not state (interpretations, none blocking)
- Email matching is case-insensitive for signup uniqueness and login (`ADA@EXAMPLE.COM` logs in).
- A whitespace-only `Idempotency-Key` is treated as empty → 400 (the spec says "absent or empty").
- Unrouted method → 405 `method_not_allowed` (a code not in the spec; it still uses the error envelope).
- Reset accepts optional `created_at`, `request_id` and `payment_id` on seeded rows.
- Risk: reset hashes every seeded password with scrypt under the global lock, at about 9 ms per user
  (500 users → 4.4 s). About 1100 or more seeded users would break the 10 s reset limit. No stated fixture size reaches that.
