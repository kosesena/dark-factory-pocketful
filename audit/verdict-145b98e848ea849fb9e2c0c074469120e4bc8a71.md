# spec-auditor verdict — stage 1, revision 145b98e848ea849fb9e2c0c074469120e4bc8a71

**REJECT 145b98e.** Two open gaps cite spec sentences. Both are regressions from the Decimal change and both were OK in 69289b3.

## Blocking gaps
- **G1 — §5 "Requests must not produce 5xx responses."** `POST /payments {"to_handle":"bob","amount":1E+999999999}` →
  `500 internal_error` ("Overflow"). It should be 422 validation_failed (the amount is above the maximum). Any number whose exponent is
  above Decimal's Emax, anywhere in an idempotent body (unknown fields too: `"x":1e1000000`), crashes
  `common._norm`, because `v.to_integral_value()` raises `decimal.Overflow`.
  Probe: `R16/R44 exact and huge numbers never 5xx`.
- **G2 — §7 "Same key, different body | 409 `idempotency_key_reuse`" / "\"Same body\" means the same JSON value after
  parsing".** With key K, `{"to_handle":"bob","amount":1,"x":1.5}` → 201, then `"x":"1.5"` → **200** (should be 409).
  The same happens with `1e40` vs `"1E+40"`. In the other direction, `"x":1.50` then `"x":1.5`, the same number, → **409** (should be 200).
  `_norm` turns non-integral Decimals into `str(v)`. Probe: `R59 number identity`.
