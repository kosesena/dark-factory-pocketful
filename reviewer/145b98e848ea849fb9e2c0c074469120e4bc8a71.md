## Finding

### 1. Body identity still distinguishes equal JSON numbers written differently
- Requirement: §7 "'Same body' means the same JSON value after parsing — key order and whitespace do not matter"; "Replay: same key, same body → 200, body identical to the original response".
- Evidence: `_norm` (common.py) maps a non-integral Decimal to `str(v)`, which keeps trailing zeros and exponent form. Integral values of 10^30 or more also go through `str`.
- Reproduction (one user, balance ≥ 1):
  1. `POST /payments`, key K, body `{"to_handle":"b","amount":1,"x":1.5}` → 201.
  2. Repeat with key K, body `{"to_handle":"b","amount":1,"x":1.50}` → **409 idempotency_key_reuse**; expected 200 with the original receipt.
  - The same happens with `x: 1e30` then `x: 1000000000000000000000000000000`. `15e-1` vs `1.5` happens to pass.
- I raised this as finding 5 in the 41a37ee reject. It is still present.
- Smallest fix: compare normalised exact values, e.g. `v.normalize()` for non-integral Decimals and `int(v)` for every integral one. Then equal values compare equal while `1` vs `1.0000000000000001` and `0.1` vs `0.10000000000000001` stay different (both still 409 here, as they should).
